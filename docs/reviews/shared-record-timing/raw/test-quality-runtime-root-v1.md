## Findings

1. **The committed native image-preflight regression does not prove absence of real FX preparation.** `packages/segno_engine/src/test/test_engine_core.c:32027-32042` passes an image with only `revision` set and asserts a counter for hook event 4. That hook sits *before* `le_fx_prepare_capture` (`packages/segno_engine/src/core/engine_commands.c:1621-1630`); no FX lane or recipe makes preparation reachable, and the test has no allowed-acquisition positive preparation control. It catches movement of the outer guard but could stay green if a later change performs real recipe preparation before refusing a pending-timing acquisition. Use a valid nontrivial lane FX recipe and a positive allowed-record control, then observe actual recipe preparation/admission or its resource effect. The independent native probe already exercised this exact contract with a real Drive recipe and a sensitive negative mutant; this finding concerns durable source/CI regression coverage, not absence of local proof.

2. **The new native-backed Dart/Session checks can be silently skipped by published CI.** `test/session/record_timing_persistence_test.dart:48-52` skips without `SEGNO_ENGINE_LIB`. The root `build` job (`.github/workflows/main.yaml:17-36`) runs root tests without that variable. The job that does set it invokes root `flutter test --tags fuzz` and `packages/looper_repository` fuzz tests only (`main.yaml:324-355`); the new Session test has no fuzz tag. The new FFI timing checks in `packages/segno_engine/test/pumped_native_engine_test.dart:1,823-836` are fuzz-tagged, but there is no `segno_engine` Dart test invocation in that job or a per-package test job. Thus these tests can contribute a green skip on a PR even though local frozen-library runs passed. Wire the two intended suites into a native-library CI step, with a check that the library path is set and tests execute. Keep the C native-test job; it covers a different seam.

## Pending source/test deltas and bounded limitations

Recheck both after that delta lands; this report is bound to the pre-repair owner/native freeze and the inspected App-test revision.
- The new Dart bridge copies track timing from the full snapshot's flat array in `NativeAudioEngine.snapshot`. Existing `engine_snapshot_test.dart` and `pumped_native_engine_test.dart` assert steady-state timing values but do not force publication between the full snapshot and later standalone track reads. The accepted plan asks for that interleaving; the oracle calls its independent negative control bounded if a fixture seam permits it. This remains an explicit test gap rather than a discovered product error. Native coherent-tuple probes cannot substitute for the Dart multi-call join.
- Native-backed Session and package Dart tests were run locally with the frozen M3.15 library according to coordinator evidence, while the independent native matrix covered 17 distinct groups and both required negative controls. This review did not re-execute those gates, measure coverage, or infer physical-device behavior. Source fixture repairs in Control, LooperPage and LooperBloc were still in progress at this read and are not certified here.

## Coverage quality observed

The Settings checkpoint suite enumerates all ten scalars, malformed values, mutation-after-write, exact absence and explicit zero; owner and repository tests exercise provisional readiness, held versus durable memory, receipt mismatch and bounded startup failure. The actual-App cases cover startup recovery, pending power-off writes, keep-playing/retry and capture-time held cleanup with the real app ownership graph. The native C tests include odd/even tuple publication, callback capture refusal, owned cancel and receipt wrap. Assertions generally use literal observed values and real downstream state rather than merely matching conversion code. The two findings above identify where a green run could overstate behavior.
