# Test-quality review — shared Click volume

The model/UI and fixture changes were reviewed by one cross-author reviewer; runtime and root integration were reviewed by another. Each applied VGV, architecture, test quality, simplicity, and readiness perspectives sequentially. These are not five distinct reviewers. The reviews assessed source and reported evidence without running additional tests or editing product code.

Model tests pin literal physical/normalized vectors, the exact canonical Click key, rejected aliases and extra coordinates, the `.01` relative step, null-versus-zero availability, and the Click destination with no output bus. Editor journeys cover Add/Save/Cancel, new External button current/current endpoints, expression and MIDI full-range defaults, stale picker availability, and repair that preserves authored endpoints. They inspect the saved mapping and absence of an audio write on Save. Actual-unit readout and accessibility text agree on percent of unity.

Runtime tests exercise a pending native command, stale same-value readback, exact absent/present scalar rollback, stopped deferred intent, held Released persistence, replay timeout/mismatch, and source retirement. The final recovery tests force a one-shot checkpoint-read failure, then attempt ordinary and controller writes before Retry: both refuse without scalar or audio writes. Session capture is blocked until Retry. A distinct-value old-rollback/new-rig-replay test detects the former wrong-gain correction. The author-focused runtime suite passed 60 tests; an independent frozen-native probe passed 55 literal cases, including the previously failing replacement-gain case. These are separate from UI tests and were not executed by these reviewers.

The App tests exercise delayed persistence, visible Retry/Keep playing after refusal, no halt on failure, and a fresh MIDI event after goodbye begins. Native-backed Session tests check durable Click capture while held and Save/recall ordering; they require the native test library. The four legacy fixture suites passed 137 tests after accurately modeling Click readiness and repository state, without loosening existing musical assertions. Four new author-only screenshot comparisons show Click MIDI endpoints, its Outputs destination, External Held/Released endpoints, and the failed-shutdown recovery dialog. Those images prove rendered states, not callback acceptance or recovery behavior.

The ordinary native-free app aggregate reported exit 0 with semantic pass. It excludes screenshot-tagged tests. After that aggregate, the External screenshot test changed only import order and a wrapped finder line; strict scoped analysis on all seven owned Dart fixture files found no issues. The final source binding and verification record must distinguish that lint-only post-aggregate delta. Remote CI and physical controller/device behavior are not inferred from these local results.
