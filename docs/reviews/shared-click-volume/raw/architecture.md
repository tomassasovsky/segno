# Architecture review — shared Click volume

Scope: model/resolver/catalogue and editor pages; `TempoCubit`, `ControlCubit`, `LooperRepository`, and `SettingsRepository`; App power-off and Session integration; touched fixture and screenshot files. Base revision: `42e5e849ec21bc5cd6a6feae0251a96923556ba7`. The final Tempo hash is `9641371bd07d7c6319ff4762bd9698dfc275b46d797131211b09cabbae7a34d9`; App source is `6429bf6a542735b99d692717cce24960e611d88c45d6e25b4231677c62d8050f`.

The model/UI and runtime/root scopes were reviewed by different cross-author reviewers. Each reviewer applied the five perspectives sequentially, rather than five separate reviewers conducting five independent passes. The reviews made no source changes.

The dependency direction remains presentation → Cubit/owner → repository → engine or settings. `ControlCubit` depends on a narrow `ClickVolumeControl` port, not the Tempo presentation type. App provides the same Tempo instance to the UI and control owner, with consumer shutdown preceding owner shutdown. Nullable accepted Click volume is the availability signal: null means unavailable during initialization, while physical zero remains a valid silent value. The catalogue accepts that owner value explicitly; it does not infer availability from transport state or output bus count. Click has one stable destination distinct from Master and output level.

Tempo serializes ordinary and controller writes, scalar persistence, and replay observation. The repository owns native command publication, readback, and the restart block. `_clickRecoveryPending` joins the local recovery record with the repository block, so failed checkpoint adoption cannot leave an admission gap. On Retry, an old scalar obligation is restored first. If the device lifetime changed, Tempo adopts the replacement's confirmed gain separately and checks lifetime again before applying it. Session Save and recall take Mixer then Click exclusivity; no reverse Click → Mixer lock was found.

Power-off establishes a synchronous controller ingress fence before its first awaited flush. Retry preserves that fence while recovering Mixer/Click and draining previously accepted cleanup. Keep playing explicitly reopens normal operation. The reviewed root App and PowerOff paths do not create a second Click state store or bypass the owner through a widget. No circular dependency, duplicate owner, or new native API was found in the final scope. Native callback timing and appliance shutdown remain separate verification domains.
