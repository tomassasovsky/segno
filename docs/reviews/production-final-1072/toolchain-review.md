## Build and connectivity gates traced

- `build.sh` fails on subprocess errors and uses a fresh temporary DSN/session directory. It generates circuit/schematic/placement, routes the explicit critical paths, rejects critical-stage native violations other than temporary dangling ends, then imports the new router session. `router.py` checks the import return value and restores the original full-precision eight USB networks.
- `finish.py` snaps only non-USB same-net nodes within 2 µm. The screen stack is defined locally there: two 35 µm copper faces, 1.53 mm core, purple mask. The separate `board_stackup.py` is used by other boards and is not a hidden dependency of this screen build. There is no production file named `fabrication.py`; the relevant package checker is `docs/reviews/screen-power-rev-l-1072/verify_fabrication.py`.
- `round_routes.py` retains endpoint anchors, pad/via contacts, same-net interior contacts, widths, layer/net assignments and locked/USB exclusions. New copper is checked against foreign tracks, pads, vias, board edges and track keepouts. It reports corners it cannot round; it does not assert that every eligible corner was rounded. That finish criterion is covered by the separate actual-board geometry review, not implied by its exit status.
- `cleanup.py` refills and saves zones, removes only native-reported short/redundant dangling router tails, refills again, then rejects either native violations or unconnected items. The final `check.py` repeats fresh all-severity DRC/ERC, including exclusions and unconnected items, and compares a freshly exported schematic netlist to the generated netlist.
- The full checker covers exact component/pad-net inventory, explicit electrical pin contracts, all relay contact states, console GPIO copper continuity, two-layer outline/zone policies, hand-solder holes, model presence, USB continuity/width/layer/skew/return-plane coverage and current-carrying paths. High-current paths are evaluated with all pours removed; the fuse-pad bypass is removed when checking the three-via transfer. Thin or missing tracks cannot be rescued by a retained power overlay.
- I read every negative-control implementation and the mandatory 56-name list. Fault selection is checked where the actual power geometry is mutated. Model, layer, hole, electrical connection, USB cut, reference-plane, power-width, taper and via faults are required to fail; the baseline/NC-isolation cases are required to pass. This review did not repeat the already recorded complete self-test run.

## Publication and independent comparison

`export.py` builds every artifact in a new directory after fresh validation. CLI export failures abort. It checks portable model resolution, basic essential layer/drill presence, copies the exact native board and documentation, inventories source/artifact hashes, rejects source changes across the export, and publishes a complete directory with rollback retaining the previous package on failure. A source hash records which generator was present; by itself it is not proof that an arbitrarily edited native board was regenerated from that source. The independent source/native geometry reviews provide that separate evidence.

The independent fabrication verifier does not import the generator/checker/exporter. It checks the complete package/manifest/source inventory, exact native copy, packaged validation source hashes, exact ZIP membership/bytes, fresh seven-layer Gerbers and separate plated/nonplated drill files/maps, two-layer 1 oz job declarations, and strict timestamp-only CAM normalization. PDF drill maps are compared by decoded page content/resources, not whole-file metadata. It rechecks the source/package/published ZIP and its own hash before success. Non-CAM PDFs, STEP and renders receive hash/inventory checks, not independent regeneration; visual/mechanical review remains separate.

No `.github/workflows` job invokes the KiCad build, native CAD checker, rounding tests or fabrication verifier. `main.yaml:412` tests the software screen-power lifecycle, which is a different gate. Local current-source CAD/CAM evidence must therefore be stated explicitly; CI green must not be presented as CAD validation.

## External-review adjudication relevant to this circuit

- The claim that `TLP627M(E` is malformed is false. Toshiba's [current orderable-part table](https://toshiba.semicon-storage.com/us/semiconductor/product/isolators-solid-state-relays/detail.TLP627M.html) explicitly lists that exact order code.
- The external report incorrectly calls Q3/Q4 S1/G2/D3. Vishay SUP70101EL is G1/D2/S3; the circuit, schematic and native pads use the correct mapping. The TN0702 relay drivers, a different part, are S1/G2/D3.
- The [Littelfuse 251 specification](https://www.littelfuse.com/assetdocs/fuse-251-datasheet?assetguid=f47a0bb7-8ede-4679-9646-7114c3787688) guarantees at least four hours at rated current and at most one second to clear 200% for these ratings. A 4 A fuse is not a 3 A limiter, and a 750 mA fuse is not a 500 mA limiter. The stated 3 A/500 mA operating ceilings must not be represented as guaranteed fault protection. A sustained 3.5 A partial fault is not guaranteed to clear the 4 A main fuse; its 3 A screen-side termination has no documented fault-rating guarantee. This is a real protection boundary, but it does not establish overheating of the specified 20 AWG copper or a normal-load PCB failure. Full short-circuit/partial-overload survival is not qualified by the current fuse selection; changing only a nominal fuse number would not create an exact current ceiling.
