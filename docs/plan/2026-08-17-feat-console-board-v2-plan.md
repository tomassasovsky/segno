## feat: console board v2 — RP2350 on the Pi's GPIO carrying the rear-panel I/O

Tracking [#747](https://github.com/tomassasovsky/segno/issues/747) ·

## Overview

Add `hardware/kicad/console_board.py` — a SKiDL generator, alongside
`main_board.py` and `ring_board.py`, for the **10-pedal console's** control board.
The board lies flat on the bottom plate beside the Pi, links to the Pi's 40-pin
header over a short keyed ribbon, and carries a **Pico 2 (RP2350)** module, the
**MIDI front end**, and JST headers for every pedal and every rear-panel connector.

This plan delivers the board **netlist-complete and layout-ready**, with an
in-generator assertion suite. Layout, fabrication, firmware and the Pi-side
transport are staged behind it (see Non-goals).

## Problem Statement / Motivation

The Pi 5's four USB-A ports are exactly consumed — two touchscreens, two rear-panel
couplers — and a hub is ruled out, so the Pro Micro cannot have one. Its only
hardware UART (`Serial1`, D0/D1) is already the DIN-5 pair
([`main_board.py:98`](../../hardware/kicad/main_board.py)), the ATmega32U4 has no
second one, and D0 has **no merge gate** (`midi_in_opto += uart_rx`). Every escape
needs new hardware; this makes that hardware do the whole job instead of patching
around a USB shortage.

An MCU has to remain regardless: `rpi_ws281x` drives the legacy PWM/PCM+DMA
peripherals and **does not support Pi 5**, whose I/O moved to RP1. The repo already
concluded this — `firmware/led_driver/` exists to offload WS2812 timing to an
RP2040.

## Proposed Solution

One flat board, ~130 × 90, THT throughout, generated by SKiDL exactly as the
existing boards are.

| block | parts |
|---|---|
| MCU | Pico 2 (RP2350) on 2×20 THT headers |
| Pi link | 2×20 **shrouded, keyed** IDC → UART ×2, SWD, power button, 5 V, 3V3, GND |
| MIDI IN | H11L1 at **3.3 V** → Pi `uart0` RX · 220 Ω · 1N4148 · DIN pin 2 **not** connected |
| MIDI OUT | 74AHCT125 ← Pi `uart0` TX · 2 × 220 Ω |
| Footswitches | 10 × JST-XH 2-pin + 100 nF RC debounce (V1 idiom) |
| CTRL 1/2 | 2 × JST-XH 3-pin → ADC (GP26–28) with pull-up |
| Indicators | 1 × JST-XH 3-pin, WS2812 chain via 74AHCT125 3V3→5 V |
| Ring/encoder | 1 × JST-XH 8-pin to `ring_board` |
| Power button | 1 × JST-XH 2-pin, passed straight through to a Pi GPIO |
| Power in | 1 × JST-XH 2-pin, 5 V from the external potted buck |

### Two rails, deliberately

Carry V1's split: `+5V` (logic) separate from `+5V_LED` (WS2812 ring, indicators,
encoder). LED transients stay off the MCU rail. See `main_board.py` nets.

## Technical Considerations

### The link is inherently back-power-safe, and that is not an accident

Into the Pi we only ever drive **through the 1k8 series leg of the divider**
(MCU TX → Pi RX). The other direction drives the *MCU*, not the Pi. So if the MCU's
rail is up while the Pi's is not, the current into a Pi pin is limited by 1k8 rather
than by an unbuffered CMOS driver. Worth stating because it is easy to "improve"
this into a buffer later and lose the property.

### The ribbon must be keyed

A 2×20 IDC plugged in reversed puts 5 V onto GND pins. Specify a **shrouded header
with a polarising notch** on the board side and a keyed IDC socket on the cable.
This is the single cheapest mistake to design out.

### SWD works on a blank chip

The Pi reflashes the MCU with openocd over SWCLK/SWDIO/GND. This works from the very
first power-on — no bootloader needed, no BOOTSEL gymnastics on a board buried under
a 16" screen. **Requires `openocd` in the Pi image**, which is a deploy work item,
not a board one.

### Cross-artifact gate: the board cannot drift from the panel

`segno_enclosure.py` owns `REAR_IO_STATIONS`. Rather than duplicating that list, the
enclosure generator emits `hardware/enclosure/out/rear_io_stations.json` and the
board generator **asserts a header exists for every station it should terminate**.
A connector added to the panel with no home on the board then fails a gate instead
of being discovered during assembly.

Direct import is not viable — `segno_enclosure` needs `cadquery`, which the KiCad
venv will not have — hence the JSON handoff.

### Assertion suite, in the house style

`segno_enclosure.py` proves its geometry with in-generator gates, each
negative-controlled. The board generator adopts the same idiom:

- no GPIO assigned twice
- ADC nets land only on GP26–28
- UART nets land only on UART-capable pins
- every net has ≥2 pins (nothing floating)
- exactly 10 footswitch headers; every rear-panel station accounted for
- `--selftest` flips each gate and exits 0 only if **every** gate bites

### Toolchain reality

`skidl` is **not installed anywhere in the repo** — the existing `.net` files were
generated ad hoc. This plan adds `hardware/kicad/.venv` (mirroring
`hardware/enclosure/.venv`) plus a `requirements.txt`, so the generator is
reproducible. Netlist generation also needs KiCad's symbol libraries present, so
**these gates are local-only** — there is no board CI today and this plan does not
add one.

## Implementation

Layered, per AGENTS.md — each step leaves something that works.

- [ ] `hardware/kicad/requirements.txt` (`skidl`) + `hardware/kicad/.venv`, mirroring `hardware/enclosure/.venv`
- [ ] Confirm `main_board.py` still generates in that venv — proves the venv before new work rides on it
- [ ] `hardware/kicad/segno.pretty/Pico2.kicad_mod` — 51 × 21, 2×20 THT at 2.54 mm, castellations optional. Model on the existing `ProMicro.kicad_mod`

### Phase 2 — the generator

- [ ] `hardware/kicad/console_board.py`: nets, rails, `R`/`C` helpers copied from `main_board.py`
- [ ] Pico 2 as a `Conn_01x20` ×2 pair (the `main_board.py` idiom for a module)

- [ ] 10 × footswitch headers + RC debounce

## Dependencies & Risks

| risk | mitigation |
|---|---|
| **A wrong netlist costs a respin** — weeks and money, unlike a code bug | The assertion suite plus the cross-artifact gate; `--selftest` proves the gates are alive rather than decorative |
| Pi 5 second-UART overlay mapping (`uart2` ≈ GPIO4/5) is unconfirmed | **Confirm on the device before the ribbon pinout is frozen.** Cheap now; a respin later |
| `skidl` version drift changes netlist output | Pin the version in `requirements.txt` |
| KiCad symbol library paths differ per machine | `main_board.py` already probes several; extend rather than reinvent |
| Pedal protocol may move to v4 (epic #442) | Board is protocol-agnostic — it carries a UART. Firmware only |
| `indicatorLeds[7]` vs 10 pills (#366) | Board wires the chain; the count is firmware. Tracked separately |
