## Material mismatches to address

- Native code already supports eight tracks, eight recording lanes per track, multilevel undo/redo, conditioning, monitoring, plugin chains, tempo/modes and capture recovery. Do not describe all of this as missing or rewrite it wholesale.
- `LE_MAX_CHANNELS` is 32, but `LE_MAX_MONITORED_INPUTS` is **8**. The accepted 18-input UX needs real monitoring/routing capacity work; drawing a longer list cannot supply it.
- Current FX topology includes non-destructive lane chains, monitor chains, track stereo buses and a master insert. Master FX process the first enabled stereo output pair, not arbitrary selected output destinations. This differs from accepted input/track Pre and Post, All tracks and per-output FX. Tail-on-bypass behavior also differs. Define and test the actual sample path before wiring those switches.
- Native mode switching still rejects changes whenever content exists. Current crown is explicitly assigned, persists through clear and cannot be unset through the exposed API; accepted behavior crowns the first completed take, allows explicit handoff and shows none for an empty session. Some interface comments still describe early mode milestones despite later implementations in `engine_process.c`; check executable handlers and tests, not comments alone.
- `LooperAction` has a small transport/metronome inventory. Existing pedal binding rules prohibit Mode remapping, unlike accepted Mode Press/Hold setup. Existing normalized targets cover FX parameters, track volume and master gain; the new parameter, external-controller and instrument catalogue requires extension with stable identities.
- No application instrument domain or native instrument-input API was found. The prototype's WebAudio instruments and sample-pack simulations are not production hosting. Reverse, Fade, Speed, Transpose, Bounce and Divide do not have corresponding named engine entry points in the current public header; establish each operation's native contract rather than treating a UI mode as audio implementation.

## Dependency-ordered vertical slices

Each slice ends with a working native-path feature, focused regression tests and an evidence record. Later slices extend it. Do not call a mocked destination finished.

1. **Main Tracks journey and shared visual foundation — recommended first slice.** Reuse startup, LooperBloc, ControlCubit and track metering. Replace the existing Tracks layout with four columns for the active bank, state colors, one whole-track meter, queue cues, FX markers, compact footer and icon navigation. Connect the small screen to the selected track waveform. Implement first-completed-take crown and empty-session clearing at the owning domain/native boundary. Accept: record Track 3, then Track 1; selection and Bank do not change playback or crown; queued actions retain their track; Mute stays in place; reload is correct. Verify widget/Bloc tests, native crown tests, desktop playback and both real displays. Preserve meter rebuild isolation and measure frame timing.

2. **Recording, timing and reversible audio edits.** Reconcile existing tempo/mode/record options with the accepted defaults and per-track overrides. Complete per-pass undo, partial-take Redo, grouped Clear All and mode-transition rules through the existing engine/repository. Accept: a one-bar partial take recovered in an established four-bar Multi loop retains three silent bars without changing mode; Redo of the defining take plays immediately; Cancel changes nothing; Clear All recovery restores the grouped audio, timing and prior playback state, preserves later Mixer/FX edits, and restores interrupted captures as stopped recoverable material. Use deterministic frame-level tests plus full pedal sequences and session round trips. Hardware proof covers timing and latency.

3. **Inputs, outputs, Mixer and FX.** Build the typed source/bus/parameter identities needed by later assignments. Extend current routing capacity, naming fallbacks, stereo/mono/pan, trim and live-only monitoring. Replace Signal-era surfaces with accepted rack/single-FX editing, shared descriptor controls and output destinations. Accept: 18 inputs remain selectable, Mixer live-input gain does not change captured audio, Solo/mute/gain remain distinct, reorder preserves assignments, Pre is printed once, and downstream tails follow the accepted Stop/Mute/Bypass/Cut sound contract. Use sample comparisons and impulse tests, not screenshots alone; verify interface ports and clipping on hardware. Do not invent unresolved Looper X descriptors.

4. **Shared assignments and foot performance.** Extend controller binding models and target resolvers; retain the ten-pedal faceplate and protocol seam. Add separate Press/Hold, fixed track targets, multiple mappings, external single/dual/expression setup, custom LED colors and the accepted foot-operated mode exits. Implement Transpose, Reverse, Fade, Multiply, Divide, Peel, Bounce, Mixer and Speed one complete native operation at a time. Accept: configurable navigation/control Hold does not also execute Press; normal Record/Play, Stop and track selection retain their defined immediate-contact behavior. Bank changes follow the agreed gesture target, momentary releases and toggle states drive LEDs, fixed external Tracks 5/6 work from Bank A, and edits have their specified Undo. Run repository/Bloc sequence tests, the existing control fuzzer and firmware protocol suite; physical footswitch and LED evidence is mandatory.

5. **Library, sessions, backing and durable recovery.** Extend session and performance repositories rather than adding a second save system. Follow accepted musical-versus-appliance ownership, New Loop preservation, audio import/export, prepared-list reorder/seek/end behavior, complete backup and repair transactions. Accept: failed writes leave the current rig and saved session untouched; Cancel retires pending actions; missing media/ports/targets are repaired explicitly; disconnect/reconnect cannot reuse the wrong USB identity; source edits and audition do not mutate saved copies. Test temporary filesystems, exact audio frames, fault injection, process termination and real removable drives. Separate crash consistency from simulated browser persistence.

6. **MIDI, external sync and instruments.** Build on shared sources and assignments, then add native instrument voices as ordinary routable audio inputs. Preserve independent MIDI ports/channels/ranges, layered instruments, full note range, remaps/chords, sustain sources, held/latch behavior, expression and audition isolation. Accept: selection never reroutes notes, release reaches its original voice, disconnect silences only affected sources, monitoring off still records through normal Tracks, missing sounds cannot appear ready, and Cancel restores the prior patch. Test event ordering and deterministic synthesis, then real keyboard, pad, expression and multi-device input. Clock loss, transport follow and reconnect need actual MIDI timing evidence.

7. **Device and appliance completion.** Reuse existing audio, network, brightness, storage, update and power services for accepted screens. Finish automatic-first latency measurement with honest fallback, per-display calibration, touch lock, USB capture limits, safe shutdown and verified update/restore. Accept: cancel/timeout preserve calibration, unavailable services are explicit, slow/full/unplugged storage safely ends capture, and failed save prevents shutdown. Run service fault tests and Linux helper tests, then appliance measurements, power interruption and both displays. These results cannot be established by the desktop radio fakes.

## Verification and completion discipline

Use current `.github/workflows/main.yaml` for exact SDKs and package coverage floors: root 90%, looper repository 95%, session 89%, performance 99%, pedal 96%, controller 82%, DAW export 100% at this inspection. Resolve dependencies first; format only edited source directories. Run analyzer, `bloc lint lib test packages`, affected package tests and root integration tests. Existing useful anchors include `test/session/session_layers_roundtrip_test.dart`, `session_fx_roundtrip_test.dart`, `test/looper/bloc/midi_looper_integration_test.dart`, `test/visualizer/`, `test/performance/` and `test/fuzz/`. Update goldens for intentional accepted changes; a screenshot is visual evidence, not transport correctness.

For native changes run `bash packages/segno_engine/src/test/run_native_tests.sh`, AddressSanitizer and telemetry-disabled variants from PROGRESS; use the C++ shim check when changing core headers. Regenerate and format FFI bindings after API edits and run `packages/segno_engine/tool/check_ffi_symbols.sh` against the built library. Test pedal protocol changes with `bash firmware/test/run_tests.sh`. Linux x64/ARM64 builds, desktop runs and actual appliance validation are distinct evidence categories. The workflow's ARM64 SDK pin differs from other jobs; verify the actual intended matrix before changing SDK requirements.

For every delivered slice record accepted behavior, changed ownership, exact checks and results, remaining hardware or reference gaps, and the saved design comparison. Never label undefined DSP or untested hardware “complete” because controls render. Run independent bug-focused and architecture/test/simplicity reviews on the final revision, honor issue/PR gates, and preserve a working app at every handoff.
