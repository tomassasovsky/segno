- `source/lib/app/track_mute.dart:39` now calls `saveLaneMuteConfirmed(channel, index, settings)`; the only producer of `muteOnly: true` is `fx_chain_persistence.dart:282-290`, always `FxStage.loop` with a non-null lane, so the `address.lane!` in the new drain branch (`:414-419`) cannot throw.

The three writers of `lane_mute.*` all remain inside `FxChainPersistence` (`:237`, `:415`, `:777`); single-queue ownership per address holds.
- **Coalescing, both orders** (`:368`, `muteOnly: muteOnly && (_dirty[address]?.muteOnly ?? true)`): FX-then-mute → `true && false` = full; mute-then-FX → `false && true` = full; mute-then-mute → scalar. A full save still writes the mute (`:777`), so no order loses either key. The superseded-entry case is covered by the drain's identity check (`:430`): if an entry arrives during the write, the loop re-iterates instead of ending, so a mute that lands mid-write converges on the live value.
- **Failure/retry/teardown unchanged in kind**: a failed mute-only write sets `attempted.failure` and clears `completeOnClose` (`:437-439`); `flush()` rethrows (`:521-524`); `close()` drops it (`:481`). A mute that coalesces onto a controller save inherits `completeOnClose: true` (OR at `:366`) and so finishes during close — exactly what the pre-existing close test asserts.

## Residuals (non-blocking, stated for the record)

1. **Running branch applies every unmute before reporting refused** — `control_cubit.dart:1950-1956`. Trigger: a per-channel native refusal of `setMute(muted:false)` for one content track. Impact: all other content tracks are unmuted (immediately audible if already playing) and persisted, no `play` is issued, and the press reports refused (dark accepted-contact LED). Old code instead left later tracks muted and earlier ones unmuted *and playing*. The new shape is the stricter one and matches `_clearAllAccepted`'s convention, so I treat it as a conscious consequence, not a defect — but no test pins it.
2. **The "mute change rewrites the chain" coupling still exists outside `applyTrackMute`** — `looper_repository.dart:3143-3153` (`_forgetLaneMutes`) notifies `onLaneChainChanged`, wired to `looper_bloc.dart:889` → `:965` → the full `FxStage.loop` writer (`fx_chain_persistence.dart:759-778`). I checked it cannot lose a stored chain: on clear this erasure is the documented contract (`looper_repository.dart:3475-3502`), and the only state where storage holds a chain the repository lacks is an incomplete boot restore — which implies no engine history (so no redo-from-empty at `:3696`) and no published record image (so not `:1149`). `stopEngine`'s notification set (`:2910`, `:2927-2929`) is empty in that state. Worth one doc sentence: review.md lines 30-31 and 57-61 state both halves without noting the asymmetry.
3. **Stale `muted` sample retained** — `fx_chain_persistence.dart:761` vs `:777` across the `saveLaneEffects` await. It converges only via the identity re-iteration at `:430`; it is why the pre-existing close test needs two write passes. The original review's suggestion to drop it was not taken. Harmless.
4. **Mute durability remains coupled to FX settlement for its address** — the mute-only entry still passes through `settleFxRecipes`/`settlePending` (`:392-405`), so an unsettled recipe can delay or fail a scalar mute save. This is required to keep one writer per `lane_mute` key and is pinned by an existing test; no simpler design preserves the ordering.
5. **Dead test scaffolding** — `test/control/control_cubit_test.dart:196-200` stubs `laneEffects` / `laneChainEnabled` / `laneChainInheritedFrom`. They existed only for the mute path's full-envelope write; no loop-stage address appears anywhere in that file now, so nothing reaches them. Leftover artifact of the defect.
6. **Doc formatting** — `docs/code-review/track-mute-durability/review.md:17` is one ~150-column line in an otherwise 80-column file.

Complexity is proportionate: one bool on `_FxSave`, one threaded parameter, one public entry point. A direct `settings.saveLaneMute` from `applyTrackMute` would have been smaller but would create a second writer for `lane_mute.*` racing `_writeFxOwner`, so the queue-preserving form is the right one under AGENTS.md's "simplest implementation that fully meets the requirement".
