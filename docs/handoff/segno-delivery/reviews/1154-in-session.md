## Findings

### 1. Medium (introduced): the reducer erases the Stop-park latch before the stops land
- `lib/control/cubit/control_cubit.dart:1591-1597`, together with `_parkAllAccepted` at 2062-2075.
- Trigger: in Mute mode with the loop running, press Stop. `_parkAllAccepted` emits `parkedResume = running \ excluded` (2068) and then posts `stopTrack` for each running channel. `LE_CMD_STOP` is applied at the next audio-callback drain (`handle_stop`, engine_process.c:1901). The repository polls every 16 ms (`looper_repository.dart:215, 2047`) and publishes a new `LooperState` on every poll while running, because the master position changes. If a poll lands between the press and that drain, its snapshot still shows tracks playing. `running && parkedResume.isNotEmpty` is then true, so the reducer clears the latch. That happens with probability of roughly buffer period / (2 x 16 ms): about 17% at 256 frames / 48 kHz.
- Impact: the next (parked) snapshot projects `armedTracks = {}`, so every Mute LED goes dark. Rec/Play then takes the empty-set fallback (1946-1950): it unmutes and resumes every content track, including the members the user had excluded or muted. This breaks the plan's rule that the resume set is latched "at PARK INTENT time". No invariant fires, because `parked-preview-matches-resume` agrees with the empty set. Before this PR the reducer only pruned non-playable channels, so the latch survived. Existing tests miss it because `setEngine`/`settle` advance engine truth first.
- Smallest fix: clear on the parked-to-running edge, not on "running". Read `wasParked = isParked(_looperState)` before 3454, pass it to `_reduce`, and clear only when `wasParked && !isParked(looper)`. That covers deferred launches (parked to running at commit) and immediate launches (cleared one poll later). The Stop latch (running, then running, then parked) survives. Add a cubit test: running, Stop, a further *running* snapshot, then parked; expect the latched set.

### 2. No defect: native `le_engine_stop_record_control` (engine_commands.c:2403-2413)
- Count-in begins only when `le_transport_held` is true (engine_process.c:103-111, 362), which requires that no track is recording or overdubbing. So "a Stop meant to finish a different capture while another track counts in" can arise only through a Sound-armed fire, which never defers. In that case both the old and the new code run `le_cancel_count_in` and leave the capture running. The old code finished the capture only when the cancel found nothing, which is the late landing this PR removes.
- A Stop during the grace window, on a member or a non-member, takes the same `le_cancel_count_in` → `handle_record` grace branch (1717-1727) before and after the change.
- The `armed`/`armed_trigger` bookkeeping skipped on this path was already skipped before, because `action` was forced to 0 whenever `cohort` was set. The `pending` refusal was also already gated by `!cohort`.
- The hook is test-only: it is declared under `#ifdef LE_NATIVE_TESTS` in `engine_core.h`, defined that way in `engine.c`, and the call at 2406-2408 has the same guard.
- The test models the race faithfully. The hook runs after the atomic reads and before `le_push`, and advances one bar plus 512 frames in 64-frame blocks, which passes the commit and the one-drain grace close (5936-5941). Without the fix, the action-0 RECORD would request a master finalize. With a seam of sr/100 = 80 frames, the following `tg_advance(256)` would set `master_length_frames` and leave the state at PLAYING, so the asserts discriminate.

## Optional notes (not introduced here)
- A late but cancel-intended Stop still produces a tiny master when the whole press arrives after the grace closes. The stale polled UI can show the countdown for up to about 16 ms after the commit, while the grace lasts one block. The control read then sees a fresh RECORDING defining take with no cohort, and action 0 finalizes it. The PR closes only the read-to-push gap. If the plan's "must not manufacture a tiny master" is meant as a guarantee, add a minimum-length (or "started within N ms of a commit") guard in `stop_record_control`. Otherwise record this as a known limit.
- In the parked branch of `_muteTrackPressed` (2127-2134), deselecting a member while its play is still pending only edits the set: it is not muted. At the downbeat the member launches audibly although its LED was dark. A second Rec/Play after such an edit cancels only the remaining members, so the deselected member still launches. Possible fix: when deselecting while `pendingLaunch != null`, also `_setTrackMute(muted: true)`.
- The Mute-entry seed is also dropped at the next running poll; a later park by any route other than Stop then shows dark LEDs. The fix in finding 1 restores this too.

Verdict: Not mergeable as-is. The native half is correct and well tested. The Dart reducer change introduces a race that erases the Stop-park resume latch; one small fix (clear on the parked-to-running edge) resolves it.
