### Required edits

**E1. Keep mixdown and stems export reachable (owner decision).** D13 and Part 1 delete `SessionRepository.exportMixdown`/`exportStems` (`session_repository.dart:593-628`) and Part 7's `Export to USB` copies only `<name>.wav`, while `DAW project` writes `project.als`/`fx-chains.txt` *inside the internal bundle*, which the user cannot reach. The capture bundle already holds `master.wav` (mixdown) and `live-input-N.wav` stems (`performance_repository.dart:979-1000`). Edit Part 7: `Export to USB` on a recording offers the DAW package: the whole bundle (master, live-input stems, `project.als`, `fx-chains.txt`) to `<mount>/Segno/Performances/<name>/`, with the single-WAV export as the other choice. Edit Parts 1/7: do not delete the session exports; re-base them on a saved bundle (`mixdown.wav` plus the live-layer `track{c}_lane{l}_L{live}.wav` renamed `_L0`), and list each session's mixdown as a `Sessions` group item in Library > Audio (pen 18/01 already has group headings such as `Backing tracks`/`Performances`) with `Export to USB` (mixdown) and `Export stems`. Record that `.als` stays capture-only (`DawManifestReader` reads `performance.json`).

**E2. D8 uses the wrong predicate.** `TransportState.isRunning` is "the audio device is open and processing" (`transport_state.dart:43-44`), not playback, so `Open` would ask on every tap. Use `LooperState.tracks.any((t) => t.state == TrackState.playing || t.isCapturing)` (`track.dart:222`, `engine_snapshot.dart:66-77`). The Part 4 widget test must drive a track state, not `isRunning`.

**E3. Audition buffer must be bounded or streamed.** D10/4.4 copy the whole file into one engine buffer and decode it with `WavCodec.decodeFloat32` on the UI isolate. `mixdown.wav` is an LCM period (`_mixdown`), and a performance `master.wav` is stereo float32 for up to 2 GB parts (accepted 6.7). Either stream through a control-thread-refilled ring (the perf ring's shape reversed) or cap the voice (state the cap, e.g. 120 s, and show it) and decode in `Isolate.run` like `readPeaks`.

**E4. Free-after-ack must prove the block finished.** 4.4 frees the parked buffer "once the ack passes the generation", citing the state-command ack (`engine_private.h:1019-1036`). The same file (`empty_command`, #1146) records that "the ack alone lands before the block's frames finish". Specify that the audio thread stores `a_audition_ack` after the last mixed sample of the block (or gate on `a_commands_published`), that a stopped callback frees immediately (no block can hold the pointer), and that a second replace while a buffer is parked waits or queues (one parked slot is not enough). Add device reopen/reconfigure (#1158) to the Listen stop triggers: configure frees the buffer, so the cubit must end Listen when `audition_frames` drops to 0 for that reason. Name the arm entry `le_perf_arm` (not `le_engine_perf_arm`); the arm applies on the audio thread (`engine_process.c:3835`), so the control-side clear plus the `e->perf.armed` skip is correct. Cite engine files as `packages/segno_engine/src/core/...`. Note the voice is summed after the bus loop, so output-bus level/mute do not affect it; only master gain and limiter do.

**E5. Stale mixdown.** `save` writes `mixdown.wav` only when the mix is non-empty and `_pruneOrphanLayers` never touches it (`session_repository.dart:500-511`). A re-save of an emptied rig leaves the previous mixdown, so Listen would play audio the session no longer holds. Part 1: delete `mixdown.wav` when `mix.isEmpty`; test it.

**E6. No load path between Part 2 and Part 4.** Part 2 deletes the Sessions dialog and makes non-current rows unopenable; `Open` arrives in Part 4. Two merged parts with no way to switch sessions is not "working end to end". Part 2 must keep `Open session` wired to the existing `loadNamed` body (by id, stopped), with D7/D8 layered in Part 4.

**E7. Align the port with #1177, and stop duplicating its copy protocol.** #1177 (`claude/usb-storage-plan-1177`, §2.3, Part 4) defines `RemovableVolume{generation, fingerprint, label, fsType, mountPoint, sizeBytes, status, ...}`, `StorageDestination`, `WriteLease{target, purpose}`, `space(destination)`, `StorageFailure{full, readOnly, volumeLost, unsupported, io}` and `copyFile(source, destination, relativePath, {ConflictPolicy})` with `.part` + fsync + rename and `Keep both` suffixing. This plan's `RemovableVolume{id, label, mountPath, freeBytes, writable}` reuses the class name with a different shape, snapshots `freeBytes` instead of calling `space()`, drops the lease `purpose` (the Storage page shows it on the disabled Eject), and Parts 7/8 reimplement `.part`-and-rename in `PerformanceRepository.copyTo` and `SessionRepository.backupTo`. Edit 4.3: key volumes by `generation`, use `mountPoint`, expose `space()`, pass a purpose into `withWriteLease`, and surface #1177's typed failures. Edit Parts 7/8: file copies go through `StorageRepository.copyFile` (or the port's equivalent); the repositories keep only bundle-level orchestration (`<id>.part/` directory, rename, `.old` swap). Also note #1177 explicitly leaves "directory listing or browsing" to this plan, so `listBackups` stays here.

**E8. The field-table test must actually fail on a new field.** Part 5 claims a later manifest field "fails that test". A hand-written table does not. Specify: construct a `Session` with every field non-default, run `rigForNewLoop`, compare `toJson()` key sets against an explicit dropped set (`tracks`, `baseLengthFrames`, `loopBars`, `primaryTrack`), and assert equality of the remaining keys and values. Enumerate `monitors`, `quantizeDiv`, `syncTempo`, `tempoSource`, `recDub`, `autoRecord`, `defaultMultiple`, `countInBars` and all `track*Overrides` in D9's keep list; they are owned settings (`settingsFromLooper`, `session_mapping.dart:103-135`) and the current list names only some.
